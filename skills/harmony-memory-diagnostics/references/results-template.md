# 结果记录模板

按用户场景裁剪，不要求固定业务流程或样本量。结果目录建议包含协议、操作事件、逐次指标、汇总、趋势图、原始内存、快照索引和根路径证据。明确 kB 转 MiB 的换算，保留实际时间戳。

每个修复 commit 均须单独生成并立即交付本模板裁剪后的报告、机器可读逐次指标表（如 CSV）及趋势图（如 PNG）。趋势图只展示两个指标：目标对象实际实例数、目标对象内存占用量；分别对比修复前后各检查点。排除类原型，标明对象类别、统计范围、单位和检查点；对象内存默认使用同一组目标实例的 self_size 合计，并明确它不包含间接持有的数据，也不是进程 PSS 或保留大小。若使用保留大小等其他口径，明确去重方法，不能混用或把它称作 self_size。目标对象不存在且类已加载时可记 0；数据不足或无法判定时标记缺失和原因，不得虚构。除非用户另有要求，不在趋势图中加入 PSS 或其他曲线；原始进程采样和报告指标表仍按需保留。报告链接 commit SHA、修复前后批次、功能结果、代码、原始采样与快照索引，并说明可比性和未解决项。原始快照与敏感日志仅留本地，不纳入源码 commit。

## 操作事件

推荐 `events.jsonl` 每条保存：实际时间、单调时钟、设备、PID、轮次、动作、前后业务状态、是否成功、证据路径。开始/停止“请求”与“生效”分别记时；若用 UI 计时器推算，记录推算误差。

## 逐次结果

| 组别/轮次 | 实际时长 | 功能/任务状态 | 开始前基线 | 稳定阶段增量 | 峰值增量 | 结束增量 | 累计结束增长 | 异常/证据 |
|---|---:|---|---:|---:|---:|---:|---:|---|
| | | | | | | | | |

上表分别对总 PSS、ArkTS PSS、Native PSS、SwapPss 记录，完整数据可展开为 CSV 列。子进程独立一表。

- 基线：指定窗口内样本中位数；不满足窗口或缺样本时记缺失。
- 稳定阶段增量：用户场景稳定窗口中位数减本次基线；稳定窗口由场景决定，不固定“第 20 秒”。
- 峰值增量：明确定义的本次操作/观察窗口内最高值减本次基线。
- 结束增量：结束观察窗口中位数减本次基线。后台任务未完成时单独标注，不称作清理完成后残留。
- 累计结束增长：各轮结束值减初始基线。

## 对比与结论

逐轮比较同口径差值，给出各组中位数、范围、样本量及末尾趋势；样本条件不匹配时不强行配对。图表标出对应的 GC/快照检查点和会影响比较的进程重启。

分别回答：有效完成多少次；稳定占用、峰值和结束增长如何变化；目标对象是否按生命周期回收；是否有可确认的强根泄漏；修复是否验证通过；还有哪些独立疑点。崩溃/卡顿区分业务、采集与收尾阶段。小样本的持续增长本身不能确认泄漏。

每个问题记录全部失败尝试及原因；只有通过真机验证的单问题修复才有成功 commit。批次关联代码版本/补丁哈希、包哈希与协议，避免把另一份代码的验证结果用于提交。
