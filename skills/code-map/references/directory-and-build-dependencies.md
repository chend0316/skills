# 目录结构图与源码地图

源码地图是未指定地图类型时的默认选择；两类图均默认交付独立交互式 HTML，遵循 [交互式 HTML](interactive-html.md) 中的展开/收起规则。页面包含完整展开的原始地图，使用 `├──`、`└──`、`│` 表达层级，目录以 `/` 结尾；原始地图不输出展开/收起标记或折叠状态示例。用户明确要求纯文本时，以 `text` 代码块交付原始地图，不生成 HTML。

## 目录结构图

父子关系只表示真实文件系统包含关系，不在此图下挂跨目录依赖。先明确根目录与过滤范围；排除生成物或只显示部分文件时说明范围，不能把过滤视图称作完整目录。

```text
module_a/
├── Page1.ets
├── common_ui/
│   └── Text.ets
└── panels/
    ├── MenuPanel.ets
    └── ChatPanel.ets
module_b/
└── common_ui/
    └── Button.ets
```

## 源码地图

有向边 `源 → 目标` 表示源在编译或构建时依赖目标；文本树的依赖子项沿这个方向展开。目录节点用于聚合依赖，不能把文件系统包含关系误判成依赖边。例中 `Page1.ets` 依赖两个 panel，`ChatPanel.ets` 又依赖两个 UI 文件；`panels/` 是依赖目标的目录分组，不表示 `Page1.ets` 位于其中。

这里的“模块”可以是用户指定的文件夹；若它不是独立构建单元，应明确说明。范围默认覆盖指定目录内全部相关源文件，不仅追踪入口可达文件；仅分析入口子图时须注明，不能据此作整个目录无外部依赖的结论。

### 原始依赖地图

展示已解析的直接依赖，每个依赖目标单独一行。重复目标可以作为引用再次出现；遇到环标注 `[循环引用]` 并停止该分支递归，不能丢掉这条边。未解析或条件不明的依赖标注 `[待解析]` / `[条件待确认]`，不能当成无依赖。包依赖和 SDK 等无仓库文件路径的目标使用包名或构建目标名。

文件下的相对依赖以该文件所在目录为基准；地图外注明图根目录及路径约定。内部身份使用规范化路径，不用显示字符串判定目录归属。

必须区分两种行语义：

- **目录结构或入口定位**：每个文件夹单独一行，逐级列出，不能把入口位置压成一行长路径。
- **依赖引用**：每个依赖目标单独一行，保留完整相对路径；同目录、子目录、跨目录以及 import/export 转导出遵循相同规则。`../../../record/Wave.ets` 与 `./src/main/ets/Wave.ets` 各是一条文件依赖，不能将 `../` 或 `src/main/ets/` 拆成目录聚合链。
- 如显式提供 `panels/` 这类依赖分组目录，须对应有意义的目录边界，且一个文件夹一行；不得仅为拆分某条依赖路径而创建分组。目录分组与文件依赖边分开保存。

例如，包入口的转导出应显示为：

```text
Index.ets
└── ./src/main/ets/recording/features/volume/feishu/Wave.ets
```


以下示例只分析 `module_a` 从 `Page1.ets` 出发的依赖，`module_b` 的文件仅作为依赖目标出现，不表示已扫描 `module_b` 全部源文件：

```text
module_a/
└── Page1.ets
    ├── ./panels/MenuPanel.ets
    └── ./panels/ChatPanel.ets
        ├── ../common_ui/Text.ets
        └── ../../module_b/common_ui/Button.ets
```

真实分析中应展示声明范围内全部已知依赖，并说明未扫描部分；不能为了缩短文本而将目录折叠或遗漏其它文件的依赖。

整个目录的交互网页使用 `scope.directory` 和 `scope.members` 声明真实成员，包含入口不可达的文件与子目录。每个成员文件独立列出直接依赖，内部目标的完整依赖在其自身条目展示，避免重复递归膨胀；引用分组只是分类，不是新目录或新依赖边。仅分析入口时保留入口递归视图并标明范围。字段格式见 [HTML 生成技巧](html-generation.md)。

### 可观测性使用点

- **埋点**：核实事件上报 API 和业务封装，记录实际 key、中文解释、事件表达式、调用表达式及文件和行号。沿常量/枚举定义和封装中的上报语句核查 key，不能把封装的第一个业务参数当成事件名。性能指标等子项按实际使用的指标 key 展示，并在解释或证据中说明它与最终上报事件的关系。
- 埋点明细在文本、HTML 文件展开、目录折叠汇总、原始地图及复制结果中统一使用 `埋点 · key · 中文解释 · 文件:行号 · 调用表达式 · 事件表达式`。例如：`埋点 · switch_fishbone_to_webview_load · 切到鱼骨图到 WebView 加载成功的耗时（仅首次加载） · modules/biz/minutes/minutes_core/src/main/ets/feature/record/MinutesRecordPage.ets:125 · mmPerfTracker.start(MmPerfMetric.SWITCH_FISHBONE_TO_WEBVIEW_LOAD) · MmPerfMetric.SWITCH_FISHBONE_TO_WEBVIEW_LOAD`。
- 中文解释优先采用已核实的定义注释或埋点文档；没有现成说明时，可依据已核实的封装行为概括，并标明“按实现概括”。保留定义/说明来源位置，不凭英文名称臆造业务口径。动态 key 保留表达式并标明“动态 key”；无法解析时标“key 待解析”，解释缺失时标“中文解释待确认”，不得省略开头字段或把猜测当成确定事实。
- **日志**：核实项目日志 API 和封装，记录调用表达式、文件和行号，以及可确认的日志级别、Tag 和消息模板。
- 只统计实际源码调用表达式，排除声明、导入、注释和未核实的同名方法。每个静态位置计一次，归到调用所在文件。业务调用和封装内部的实际调用归各自文件，不沿调用链累加。整目录覆盖范围内所有源码文件，包括无依赖边的文件。
- 文件行显示两类计数，原始地图附使用点清单。已核实无调用时省略计数标签，证据不足时标“待确认”并说明范围。交互视图通过“可观测性”独立控制两类明细和文件计数的显示。可观测性记录属于文件属性。

## 证据与迁移判断

先确定语言、构建单元、构建变体及分析范围，再结合源码引用和构建配置解析目标。覆盖 import/export（含转导出）、include、类型依赖、路径别名、包映射、模块清单与构建脚本中的依赖；按项目情况检查生成代码、编译插件与原生链接输入。同时按 [资源引用与分类](resources-and-categories.md) 梳理 `$r(...)` 等资源使用点，在所属文件下逐处列出资源类型、标识、使用位置和定义或解析状态。资源未纳入时，不据此宣称迁移后已具备完整构建输入。运行时调用、DI 或动态加载不自动等于编译依赖，需按实际机制分类。不能只凭 import 文本或运行地图认定完整编译依赖。

引用类别与目录边界分开记录：系统 API、源码依赖、外部包、构建工具等分类见 [资源引用与分类](resources-and-categories.md)。分类按钮的数量按该类别中的规范化目标去重，保留全部引用位置作为证据；分类并不把源码直接引用变成运行时调用。

回答“迁走模块 A 后是否还能编译”时，先区分迁移 A 的独立编译与原工程移除 A 后的编译；用户未限定时分别说明：

- A 的出向依赖决定它还需要携带、声明或替换哪些外部模块、包、资源及构建输入。
- 指向 A 的入向依赖决定原工程哪些调用方和构建配置需要随迁移调整。默认源码地图显示出向边；迁移分析另行核查入向边，不反转默认边方向。
- 路径重定位、别名、可见性、生成步骤、工具链和构建配置也可能影响编译。没有发现跨目录边，只能说明在已分析范围内未发现，不能直接证明可独立编译。

结论区分“发现阻碍”“静态分析未发现阻碍”“已通过构建验证”，并列出未解析项和未覆盖范围。若已执行构建，记录命令、变体、结果及适用范围；用户仅要求只读分析时不为验证改动工程或迁移文件。证据路径和行号可放图外，避免挤占树形结构。
