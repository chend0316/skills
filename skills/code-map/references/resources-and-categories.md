# 资源引用与分类

用于源码地图的资源扫描与分类。资源扫描需与源码、包映射和构建配置来自同一快照；不要把旧图中的代码边与当前工作区资源结果混在一起。

## 分类与身份

- 以边的 `category` 表达引用类别，节点 `category` 可提供默认值。依赖类型建议使用 `系统 API`、`源码依赖`、`外部包`、`构建工具`、`构建配置`、`待解析引用`，也支持项目自定义类别。旧快照的 `内部源码` 和 `外部源码` 统一显示为 `源码依赖`，目录内外边界单独标注。资源边仍可用 `资源文件` 或 `系统资源` 标识来源，但顶部仅按“资源类型”筛选这些边。
- `@kit.*`、`@ohos.*` 等系统声明可标为系统 API；`@ohos/lottie` 这类三方包不能仅凭前缀当成系统 API。未逐符号解析的系统调用、隐式 ArkUI/语言全局类型要说明范围，不伪造系统 API 边。
- 资源用 `subtype` 标注文案、图片、图标、颜色、尺寸、配置、原始文件等，用 `resourceKey` 保留原始符号。包清单依赖、类型导入、转导出及静态字面量动态导入分别保留 `type`，类别不取代依赖机制或解析状态。
- 已定位的资源采用实际文件的规范化路径，节点为 `kind: file`、`category: 资源文件`。这使模块自己的资源随折叠隐藏，其他模块资源保留为跨边界目标。同一个 JSON 的多个 key 可产生多条证据，但分类计数只算一个文件目标。
- 未定位或存在多个提供方时使用独立 `kind: resource` 符号节点，保存候选路径和原因，状态标为待解析/条件待确认。不能仅为显示路径而指向一个猜测的文件。

## 定位资源

1. 识别真实源码表达式，排除注释、字符串中的示例和方法声明。Harmony 示例包括 `$r('app.string.X')`、`$r('app.media.Icon')`、`$rawfile('file')` 及按名称查询 API。其他平台按其资源机制处理，不套用 Harmony 路径。
   同时核查 UI 组件参数、静态图片/图标导入及项目资源封装。按使用上下文区分图片和图标；无法确认时保留“图片/图标”。同一资源在不同位置使用时逐处记录；同一位置的多个定义候选合在同一条边中。
2. 用当前模块资源目录、包映射与依赖可达提供方建立定义索引。记录实际 JSON key/图片文件、定义行号、资源根及配置变体。只有全工程搜索命中、缺乏依赖可见性证据时，保留为候选并标记条件待确认。
3. 同名资源先核查当前模块和构建资源合并/覆写规则。多个提供方、产品源码根或生成资源会影响结果；不能仅按搜索顺序或最短路径选择一个提供方。
4. 一般以 base/default 定义建文件边，在 `mapping` 或节点 `definitions` 中列出语言、深色、密度等配置变体。若请求需要完整资源构建输入，进一步扫描所有适用变体、资源间别名及生成步骤，不能用默认定义冒充所有变体。
5. 动态名称、数字资源 ID、数据流传入 key 及无法定位的生成资源保留缺口。只把实际调用当成动态查询，不把 `getStringByName(name: string)` 等函数声明误认为引用。资源内容中的 Lottie/HTML/CSS 嵌套素材若未扫描，也需说明。

证据示例：

```json
{
  "source": "feature/Page.ets",
  "target": "common/src/main/resources/base/element/string.json",
  "type": "resource-reference",
  "category": "资源文件",
  "subtype": "文案",
  "resourceKey": "app.string.StartRecording",
  "status": "resolved",
  "evidence": {"file": "feature/Page.ets", "line": 12, "snippet": "$r('app.string.StartRecording')"},
  "mapping": ["common/src/main/resources/base/element/string.json:8", "其他语言变体见定义索引"]
}
```

## 生成与核查

将引用边和文件/符号节点放入同一份依赖 JSON，使用 `generate_dependency_html.py --include-resources`。每个源码使用点一条边，保存原始资源标识和使用位置；同一文件的不同 key 或不同位置不合并。依赖类型仍按目标去重，资源类型按使用点计数。生成器不会扫描资源或验证定义，输入中的 resolved 必须由源码核查支持。

核查源码引用、定义文件、变体位置、未解析状态和类别统计；确保资源进入原始图、复制、交互图与统计的规则一致。折叠与筛选只改变可见内容，不能改写图边、丢弃候选或把真实资源文件误判成永远在目录外的抽象包。
